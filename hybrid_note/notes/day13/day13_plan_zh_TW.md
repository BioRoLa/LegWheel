## 1. 一天下來學到的三件結構性事實

這三件事改變了後續該怎麼做，比任何單一數字重要。

### 1.1 腿的「時間」就是它對「車體位置」的說法

```python
start_s = (hip_x - mount - origin) / speed     # world_schedule_2d
body_x  = median(四隻 stance 腿的 hip_x - mount)  # body_trajectory_2d
```

所以**只動一隻腳的時間，它就必然與其他三隻對車體位置產生分歧**
（實測 0.000 → 84.068 mm，車體速度跳到 −167/+507 mm/s）。

四種錯開做法全部失敗且同源，詳見 `day13_findings_zh_TW.md` §2。

### 1.2 餘裕在【空間】，不在時間

nominal stroke 滾到 `RIM_ARC_EXHAUSTED`，**餘裕 0.000 mm**。
而 `run_foot_rim_roll_2d` 一直有 `max_distance_m`，
docstring 明說它是「a distance request rather than a hard-wired full arc」。

**留 10% 弧 = 16.9 mm 可調度空間，車速只掉 8%。**
而需要的錯開量是 16.5 / 35.7 mm。

### 1.3 有些「失敗」是模型的假設，不是機器人的限制

```text
body_requirement_satisfied   模型鎖死 body_rpy=(0,0,0)，車體不許傾斜。
                             剛體本來就可以傾斜 —— 四個髖點定義一個【平面】，
                             不是一個高度。54.28 mm / 510 mm 軸距 = 6.08 度俯仰。
support_margin               floor 3 mm 來自【猜測】的 ±2 mm 重心誤差，
                             而模型沒有質量、慣量、接觸力、摩擦、動力學。
motor_rate_limit             這個是【真的】，硬體規格。但可用週期直接換。
at_most_one_airborne         這個也是【真的】，且排程層解不掉（見 1.1）。
```

## 2. 現在的做法：兩段式拼接（專案擁有者提出）

> 「前段的走平地跟之前規劃的一模一樣，然後到障礙物前再停下來換成規劃障礙物的步態」

```text
[ hybrid_flat_v1 原封不動 ] + [ 停下來過渡 ] + [ 越障段 ]
      已驗證、Step 9 全過        餘弦漸變         獨立規劃、可獨立放慢
```

**為什麼這比「整條一起規劃」好：**

```text
整條一起   平地段被迫用越障的粗網格（121 點 / 38.9 s = 每點 324 ms）
           而 flat_v1 是 3960 點 / 19.8 s = 每點 5 ms
           -> 平地走起來跟已驗證的版本【差很多】（擁有者實際跑出來發現的）

兩段拼接   平地段【完全不重新規劃】，直接沿用已驗證的檔案
           越障段可以獨立用高密度網格 + 獨立放慢
```

**拼接必須處理的三件事**（都已實作，見 `day13_step5_splice_driver.py`）：

```text
1  beta 是圈數計數器   flat 結尾約 −3200 度，越障從 −40 度重新算。
                       要整體偏移，否則輪子會在一個控制週期內倒轉 8.9 圈。
2  越障規劃自帶接近段   它的車體走 148 → 1589 mm，59% 是走去障礙物的路。
                       要裁掉，否則會走兩次。
3  兩段要在姿態上接上   接點 theta 差最多 51.91 度（FL），
                       用餘弦漸變攤在停頓時間內。
```

## 4. 策略的包絡線（2026-09-07 修正後）

**這一節取代了原本的「三個地形的現況」。** 專案擁有者要的是
「跨越普遍障礙物的策略」而不是「跨越特定幾個障礙物」，
而查證發現原本的決策表有兩個 bug 讓它退化成一張查表（findings §5.4）。

修正後：

```text
        L=300      L=400      L=600
 20-30   #4         #4        拒絕
 40-100  #4         #4         #1
110-140  #4/#1      #1         #1
150-200  #4        拒絕       拒絕
```

**現在是連續的**（任何高度都有答案），而且**與頂面長度相關**——
因為 `#4` 需要一個能從落地點搆到離開點的 takeoff，
而需要的長度是 `L − 160 mm`，掃描只量到 240 mm。

### 邊界是資料的邊界，不是機器人的

```text
高度 < 20 mm 或 > 200 mm   掃描範圍外，不外插
L = 600 mm                 需要 440 mm 的 takeoff，從沒量過
SWING_OVER                 五個策略之一，【從未掃過任何高度】
```

**這些都是資料缺口，不是不可行。** 要擴大包絡線，
要做的是補掃描（尤其是更長的 takeoff 與 `SWING_OVER`），
而不是改規劃器。

### 論文能寫的最強版本

> 滾動越障在 160 mm 於所有測試的取樣密度下皆不可行；
> 140 mm 以下的可行性判準對輪緣取樣密度高度敏感
> （30 格中 22 格隨密度改變），因此不宣稱一個夾緊的滾動高度上限。
